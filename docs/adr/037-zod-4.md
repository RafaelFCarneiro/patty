# ADR-037: Move to zod 4

**Status:** Accepted · **Date:** 2026-11-16 · **Deciders:** Rafael

## Context

zod decodes every boundary in PATTY: MCP arguments, HTTP bodies and queries, CLI flags, database rows, and the
OpenAPI document is generated from the same schemas (`@asteasolutions/zod-to-openapi`). ADR-001 and ADR-003 keep zod
to that one job.

PATTY is on zod 3.25. A high-severity advisory (GHSA-mrhx-c7xc-m3w5: memory exhaustion while validating oversized
constrained collections) is fixed only in zod 4.6.6; zod 3 gets no fix. It is the only advisory left in what the
published package installs (the dependency audit, #257). Its practical reach is small (every route but login, setup,
connect and health needs a login, request bodies are capped at 1 MB, and the public forms take short strings), but
every input passes through zod, so it is fixed properly rather than accepted.

The libraries around zod are ready: the MCP SDK accepts `^3.25 || ^4.0`; `zod-to-openapi` 8 and later require zod 4;
`@rfc0/effect-runner` declares zod as a peer (`^3.25.0`) and uses only APIs that exist in both majors.

## Decision

1. **PATTY moves to `zod ^4.6.6`**, imported from `'zod'` (zod 4's root export), and `@asteasolutions/zod-to-openapi`
   to its current major. No `zod/v3` or `zod/v4` subpath imports and no compatibility layer: one zod everywhere.

2. **`@rfc0/effect-runner` requires zod 4** as a peer (`^4.6.6`), released as **1.0.0**. Its shipped type file is
   compiled against one zod major, and zod 3 and zod 4 type their schemas differently (`ZodEnum<[…]>` versus
   `ZodEnum<{…}>`), so serving both meant hand-writing a copy of zod's enum type that kept drifting from the real
   one. PATTY, its only consumer, moves to zod 4 in the same step and uses only `PersistOp.enum.*` and the type.
   Dropping a peer major is breaking for a library, so the release is honestly 1.0.0, after a long-stable API.

3. **No behavior or contract change.** The migration changes how schemas are written, not what they accept or emit:
   - the MCP surface (tool names, input schemas, descriptions), pinned by `test/unit/diplomat/mcp/__snapshots__/surface.json`,
     stays equivalent; any difference in the generated JSON Schema is reviewed and either matched or explained in the PR;
   - the OpenAPI document stays equivalent (diffed before and after);
   - error messages that reach a person (CLI, HTTP, MCP) keep their wording; tests that assert them stay unchanged.

4. **zod 4's changed semantics are checked, not assumed.** The known differences are reviewed at every use:
   - custom messages: `message`, `required_error`, `invalid_type_error` and `errorMap` become the `error` option;
   - `ZodError.errors` becomes `.issues`; `format()` / `flatten()` give way to `z.treeifyError` / `z.flattenError`;
   - `.default()` now applies to the output and short-circuits on `undefined` (`.prefault()` keeps the old
     behavior), which matters wherever a default meets a `.transform()` or `z.preprocess()`;
   - `z.record()` needs both key and value schemas;
   - `z.number()` rejects infinities, and `.int()` means safe integers;
   - type generics: `ZodType<Output, Input>` (no `ZodTypeDef`), `ZodTypeAny` → `ZodType`;
   - `.merge()` → `.extend()`, `.strict()` / `.passthrough()` → `z.strictObject` / `z.looseObject`, `.superRefine()` →
     `.check()` (the old forms still work but are deprecated; new code uses the new ones).

5. **A gate afterwards.** Once zod 4 is in, CI fails on any high or critical advisory in what the package installs:
   `npm audit --omit=dev --audit-level=high`.

## Options considered

- **Accept the advisory on zod 3.** Rejected: no fix will come, and zod sits on every input.
- **zod 4 through the `zod/v4` subpath of zod 3.25.** Rejected: the advisory is in the zod package version, and
  the fix ships only in zod 4.6.6.
- **effect-runner accepting both majors** (`^3.25.0 || ^4.6.6`, a minor release). Tried first and rejected: one
  shipped type file cannot name a zod type valid under both majors, so `PersistOp` needed a hand-written imitation of
  zod's enum type (`options`, `extract`, `exclude`), and each review round found another way it differed from zod's
  own. It protected nobody: the only consumer was moving to zod 4.

## Consequences

- The only advisory in the published package is closed, and the audit gate keeps it that way.
- A broad but mechanical change across about a hundred files; the MCP and OpenAPI snapshots catch contract drift.
- New code follows zod 4's API; `docs/architecture.md` § Conventions names zod 4.

## Plan

1. [x] effect-runner `feat/zod-4-peer` (RafaelFCarneiro/effect-runner#14): peer `^4.6.6`, `PersistOp` back to zod's own
       enum type, a built-package consumer check in CI; released as 1.0.0.
2. [x] PATTY `fix/zod-4` (#268): zod `^4.6.6`, zod-to-openapi's current major, `@rfc0/effect-runner` bumped, every schema
       migrated per §4 with the MCP surface and OpenAPI document unchanged (§3), and the audit gate in CI (§5).
